# Sheet Guard Bot

Sheet Guard Bot сверяет участников одной Telegram-супергруппы с регистрацией в Google Sheets. Он очищает некорректные ответы формы, ведёт чёрный список, учитывает точечные исключения из белого списка и при необходимости проверяет членство во второй группе.

Проект требует Python 3.10 или новее; офлайн-проверки проекта выполнены на Python 3.12. Зависимости закреплены в `requirements.txt`.

## Роли Telegram-групп

| Роль | Переменная | Поведение |
|---|---|---|
| Управляемая группа | `MANAGED_CHAT_ID` | Здесь бот удаляет участников. Он сюда не пишет. |
| Вторая группа | `SECOND_FACTOR_CHAT_ID` | Используется только как второй фактор. Бот сюда не пишет. |
| Группа логов | `LOG_CHAT_ID` | Единственное место для сообщений бота и команд `/sync`, `/check`. |

Все активные ID должны быть разными отрицательными числами. `MANAGED_CHAT_ID` должен указывать на группу или супергруппу. В ней боту нужны права администратора с возможностью блокировать пользователей. Если включён второй фактор, бот тоже должен быть администратором второй группы: Bot API гарантирует `getChatMember` для других пользователей только администратору. В группе логов бот должен состоять и иметь право отправлять сообщения.

Отключать privacy mode для события `chat_member` не требуется. При добавлении бота разрешите ему получать обновления участников.

Bot API не выдаёт полный список участников. `bot.py` проверяет вступивших после его запуска и людей из локальной базы `members.db`. Для первой полной проверки уже существующей группы служит `audit_telethon.py`.

## Таблица

Одна таблица содержит три разных листа:

| Лист по умолчанию | Обязательные колонки |
|---|---|
| `Форма` | `группа`, `username` |
| `Черный список` | `username`, `причина`, `дата` |
| `Белый список` | `username` |

Регистр и порядок колонок произвольны. Первая строка каждого листа обязана содержать все его заголовки; лист с заголовками и без данных допустим. До первой записи проверяются заголовки всех трёх листов.

По умолчанию код группы должен точно соответствовать `M31` и двум ASCII-цифрам, например `M3112`. `m3112`, `M311`, `M31123` и цифры других алфавитов не подходят. Строка с неверным кодом остаётся только тогда, когда её username есть в белом списке. Иначе username один раз добавляется в чёрный список, а строка удаляется. Запись и удаления отправляются одним запросом Sheets API; текст записывается как строка и не вычисляется как формула.

Доступ в управляемую группу разрешён, когда username есть в уже очищенной форме и отсутствует в чёрном списке. Белый список сам по себе доступ не даёт: он сохраняет строку с неверным кодом и отменяет только проверку второй группы. Чёрный список всегда имеет приоритет. Флаг `KICK_USERS_WITHOUT_USERNAME=false` отменяет лишь проверку username/формы; включённая проверка второй группы продолжает действовать.

Если Telegram или Google не подтвердили данные из-за ошибки API, бот считает состояние неизвестным и откладывает удаление. Во время повторной проверки он заново получает статус и текущий username, не удаляет ботов и администраторов и считает restricted-пользователя участником только при `is_member=true`.

## Установка и настройка

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Заполните все обязательные поля `.env`. Булевы значения принимают только `true/false`, `yes/no`, `on/off` или `1/0`; интервалы должны быть положительными целыми числами.

В Google Cloud включите Sheets API, создайте сервисный аккаунт и JSON-ключ, затем дайте email аккаунта права редактора таблицы. Укажите путь в `GOOGLE_CREDENTIALS_FILE` и ID из URL таблицы в `GOOGLE_SHEET_ID`. Drive API не требуется.

Создайте бота через `@BotFather`, заполните `BOT_TOKEN`, добавьте его в три группы с описанными выше правами. При старте конфигурация и права проверяются до создания фоновой задачи. Затем выполняется начальная очистка/синхронизация и только после неё начинается polling.

Запуск:

```bash
source .venv/bin/activate
python bot.py
```

Запускайте только один экземпляр `bot.py`. Во время очистки не сортируйте и не удаляйте строки формы вручную.

Команды принимаются только в `LOG_CHAT_ID` и только от обычного, не анонимного администратора этой группы:

- `/sync` — очистить форму и перепроверить известных боту участников;
- `/check @username` — показать прогноз по таблице и, для известного локальной базе numeric user ID, обновить текущий username и проверить вторую группу. Команда не меняет таблицу. Для неизвестного ID статус второй группы честно выводится как неизвестный.

Авторизация намеренно привязана к текущему публичному username. При смене username человек проверяется заново по новому значению; постоянное соответствие по Telegram ID проект не хранит.

## Полный аудит через Telethon

Получите `TELEGRAM_API_ID` и 32-символьный `TELEGRAM_API_HASH` на [my.telegram.org](https://my.telegram.org), а `AUDIT_GROUP_ID` задайте равным `MANAGED_CHAT_ID`. Аккаунт Telethon должен видеть обе проверяемые группы и иметь право удалять участников управляемой группы.

Сначала оставьте:

```dotenv
AUDIT_DRY_RUN=true
```

и запустите:

```bash
python audit_telethon.py
```

Dry run печатает полный список кандидатов в консоль и использует прогноз очищенной формы. Он не пишет в Sheets, не удаляет участников и не отправляет сообщения в Telegram. Первый вход Telethon создаёт локальный файл сессии.

Для реального запуска остановите `bot.py`, не изменяйте и не сортируйте таблицу параллельно, установите `AUDIT_DRY_RUN=false` и снова запустите скрипт. Успешные удаления и итог аудита отправляются только в `LOG_CHAT_ID`. Скрипт поддерживает обычные группы и супергруппы, повторно проверяет членство, права и текущий username непосредственно перед удалением, а сбои API откладывает.

## Офлайн-проверки

Проверки не подключаются к Telegram или Google и не используют секреты:

```bash
source .venv/bin/activate
python -m unittest discover -s tests -v
python -m compileall -q config.py google_sheets.py storage.py bot.py audit_telethon.py tests
python -m pip check
```

Тесты проверяют строгую конфигурацию и шаблон, переставленные/разнорегистровые заголовки, пустые валидные листы, отсутствие обязательных колонок, дедупликацию и безопасную запись строк, согласованный dry run без записей, конкурентную очистку, приоритет чёрного списка, точное действие белого списка, второй фактор для пользователя без username, ошибки API без удаления, restricted-статус, обновление username, изоляцию команд, numeric ID в `/check`, защиту администраторов и полностью read-only аудит.
